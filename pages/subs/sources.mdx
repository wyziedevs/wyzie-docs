# Wyzie Subs Sources

<TP id="subs.sources.p1" />

## Using Sources

Use the `source` parameter to specify which provider(s) to query:

```
/search?id=tt3659388&source=charlie&key=YOUR_KEY
/search?id=tt3659388&source=charlie,lima&key=YOUR_KEY
/search?id=tt3659388&source=all&key=YOUR_KEY
```

## Health Checks

Every source is checked once an hour with a real search and a real subtitle download. A source that fails two checks in a row is **paused**:

- it is left out of `GET /sources` and out of `source=all` until it passes a check again
- a search that names only paused sources (for example `source=lima` while lima is paused) returns `503` with `"message": "Source temporarily offline"` and is not billed; name a live source alongside it, or use `source=all`
- a search that mixes live and paused sources runs the live ones and lists the paused ones in the `X-Sources-Offline` response header

Paused sources are re-checked every 15 minutes and return automatically. [sub.wyzie.io/status](https://sub.wyzie.io/status) shows every source, including paused ones, and `GET /api/status` returns the same data as JSON (`listed: false` marks a paused source). Treat `/sources` as the live list rather than hard-coding it.

## API Endpoint

<TP id="subs.sources.api.p1" />

```
GET /sources
```

Returns:
```json
{
  "sources": ["charlie", "foxtrot", "india", "juliet", "lima", "mike", "november"],
  "free": ["charlie", "lima"],
  "paid": ["foxtrot", "india", "juliet", "mike", "november"],
  "tiered": [
    { "key": "charlie", "name": "charlie", "tier": "free", "tags": [] },
    { "key": "foxtrot", "name": "foxtrot", "tier": "paid", "tags": ["anime"] }
  ],
  "allFree": false
}
```

- `free`: <T id="subs.sources.api.free" />
- `paid`: <T id="subs.sources.api.paid" />
- `sources`, `free`, `paid`, `tiered`: live sources only; a source paused by its health checks is missing from all of them until it recovers.
- `tiered`: one entry per live source with its `key` (the value to pass as `source`), display `name`, `tier` (`free` or `paid`), and `tags` (for example `anime`). The example above is shortened.
- `allFree`: <T id="subs.sources.api.allFree" />

### Scoping to a key

<TP id="subs.sources.scope.p1" />

```
GET /sources?key=YOUR_KEY
```

<TP id="subs.sources.scope.p2" />

```json
{
  "sources": ["charlie", "foxtrot", "india", "juliet", "lima", "mike", "november"],
  "free": ["charlie", "lima"],
  "paid": ["foxtrot", "india", "juliet", "mike", "november"],
  "tiered": [
    { "key": "charlie", "name": "charlie", "tier": "free", "tags": [], "available": true }
  ],
  "key": { "valid": true, "type": "free" },
  "available": ["charlie", "lima"],
  "restricted": ["foxtrot", "india", "juliet", "mike", "november"],
  "allFree": false
}
```

- `available`: <T id="subs.sources.scope.available" />
- `restricted`: <T id="subs.sources.scope.restricted" />

You can also view the real-time status of all sources at [sub.wyzie.io/status](https://sub.wyzie.io/status).

## Source Details

Sources are exposed under NATO codenames. Pass the codename as the `source` value; `source=all` works for every key and queries each source that key can use. The list below reflects the live `/sources` response and can change, so fetch it at runtime rather than hardcoding it.

| Source       | Tier | Tags  |
| ------------ | ---- | ----- |
| **charlie**  | Free |       |
| **foxtrot**  | Pro  | anime |
| **india**    | Pro  |       |
| **juliet**   | Pro  | anime |
| **lima**     | Free |       |
| **mike**     | Pro  | anime |
| **november** | Pro  | anime |
